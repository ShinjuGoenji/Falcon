# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Goal

ASIC hardware implementation of `Zf(sign_dyn)` (Falcon-512 signature generation) in SystemVerilog, targeting TSMC 28nm HPC with ARM Artisan Physical IP. Reference: `doc/FalconSign` (paper PDF) and `doc/implementation_plan.md`. The software reference implementation lives in `software/` (C99, Thomas Pornin / NCCGROUP).

**Target specs:** 0.71 mm² @ 530 MHz, ~264k cycles, 4 BFU parallelism.

## Shell Requirement

All EDA tools (VCS, DC, Verdi) **must run in `csh`** (C Shell). Do not use bash for EDA commands.

## Common Commands

Each hardware module follows the same structure. Run from `hardware/<module>/00_TESTBED/`:

```csh
# RTL simulation
make vcs_rtl

# Gate simulation (after synthesis)
make vcs_gate

# Synthesis (Design Compiler)
make syn

# Open waveforms in Verdi
make verdi_rtl
make verdi_gate
```

Software reference (from `software/`):

```bash
make test_falcon    # build + run correctness test
make speed          # benchmark
make clean
```

## FP Unit Design Decisions

- **DesignWare IP** (`DW_fp_add`, `DW_fp_mult`, `DW_fp_div`, `DW_fp_sqrt`) — not custom RTL.
- `ieee_compliance=0` (no Inf/NaN/subnormal handling; safe for Falcon's bounded arithmetic).
- Rounding: round-to-nearest (`rnd=3'b000`).
- 64-bit IEEE-754: `sig_width=52`, `exp_width=11`.
- `FPR_ADD.v`, `FPR_MUL.v` are thin wrappers around DW primitives; `FPC.v` builds complex ops on top.
- `FPC_MUL` and `FPC_MULADJ` are **2-cycle pipelines** (mul stage → add/sub stage).
- `FPC_ADD`, `FPC_SUB`, `FPC_MULSELFADJ` are **combinational**.

## Testbench Pattern

`PATTERN.sv` reads test vectors generated by `hardware/<module>/golden/` Python scripts (e.g., `gen_fpc_vectors.py`). Input/output hex values are stored in `.txt` files. At end of simulation, `PATTERN.sv` prints `total_pass` / `total_fail` counts.

For pipelined modules, `PATTERN.sv` sends `in_valid` and checks `out_valid` N cycles later matching the pipeline depth.

## Architecture Context (sign_dyn)

The top-level `Zf(sign_dyn)` FSM drives these operations (from `doc/implementation_plan.md`):

- **ffSampling** — 4-state recursive FSM: `RIGHT_DOWN`, `RIGHT_UP`, `LEFT_DOWN`, `LEFT_UP`
- **ffLDL** — uses `fp64_div` (LDL step) and `fp64_sqrt` (leaf node, level 9)
- **SamplerZ** — 74 cycles/sample pipeline (BaseSamp + BerExp)
- **BFU cluster** — 4 parallel BFUs shared by FPU, LDL, and Sampler via time-multiplexing
- **Memory** — 4 × 16KB ARM Artisan single-port SRAM banks + 8KB Twiddle ROM

Task format is 68 bits: `src_addr_A | src_addr_B | dst_addr | vector_len | opcode | level | index`.

Supported opcodes: `FFT, IFFT, SPLIT, MERGE, LDL, MULSELFADJ, MULADJ, MUL, ADD, SUB, NEG, MULCONST, SQRT_NORM, SAMPLE, INT2FPR, FPR2INT`.
